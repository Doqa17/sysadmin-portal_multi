📘 Инструкция по настройке

Нужно разрешить серверу Exchange выполнять действия от имени портала.
  1. На контроллере домена откройте dsa.msc (AD Users and Computers).
  2. Перейдите в корень домена -> Microsoft Exchange Security Groups.
  3. Найдите группу Recipient Management.
  4. Добавьте ваш сервисный аккаунт (Bind User) в члены этой группы.

Разрешаем сетевое подключение к PowerShell:
  1. Зайдите на сервер Exchange.
  2. Нажмите Win+R -> compmgmt.msc (Управление компьютером).
  3. Служебные программы -> Локальные группы -> Группы.
  4. Найдите группу Remote Management Users (Пользователи удаленного управления).
  5. Добавьте туда ваш сервисный аккаунт.

В консоли PowerShell на сервере Exchange выполните: winrm quickconfig Проверьте, что в настройках портала указан **DNS-FQDN** сервера (например, mail.domain.local), а не IP-адрес. Kerberos не работает по IP.

Если права выданы, но ошибка остается:
  1. Откройте services.msc на сервере Exchange.
  2. Найдите Службу веб-публикаций (W3SVC).
  3. Перезапустите её (это сбросит кэш прав Exchange).
Важно для безопасности:
Портал подключается по порту 80 (HTTP), но использует стандартную шифрованную аутентификацию Kerberos. Передача данных внутри сессии полностью защищена.
